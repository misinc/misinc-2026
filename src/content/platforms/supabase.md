## Not a website platform

Worth saying plainly, because it is easy to assume otherwise: Supabase is not something we build websites on. It is the layer underneath applications — the database, the user accounts, the file storage, and the security rules.

When a project needs people to log in, data to be stored and queried, or logic that runs on a schedule, this is what we use.

## Why Supabase

**It is Postgres.** Not a proprietary datastore with a proprietary query language — the most widely used open-source relational database there is. Your data is in a standard format that any developer can work with, and that you could take elsewhere.

**Authentication is solved.** Sign-in, password resets, and access rules are handled properly, which matters because authentication is easy to get subtly and dangerously wrong.

**Row-level security.** Permissions live in the database itself, so a mistake in the interface cannot expose data it should not.

**It scales down.** Small projects cost little or nothing, which keeps custom software viable for businesses that could not justify enterprise pricing.

## What we build with it

Client and member portals, internal tools that replace fragile spreadsheets, booking and intake systems, and the data layer behind AI agents that need to look things up in your own records.

It pairs naturally with [Astro](/platforms/astro) — static, fast public pages, with an application behind the login.

## What to know

This is custom development, so it carries a development cost and needs someone to maintain it. We build the smallest thing that solves the problem for exactly that reason, and we use boring, well-documented technology so you are not dependent on us specifically.
